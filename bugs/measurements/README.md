# Замеры на живой модели

Все числа сняты настоящими вызовами модели ключом продукта, а не оценены.
Суммарно потрачено около **$3,00**.

## Файлы

| Файл | Что в нём | Как читать |
|---|---|---|
| `big_result.json` | **Главный.** По 5 прогонов на клетку, полным циклом с повторами | На нём основана правка 02 |
| `effort_result.json` | Три главы × три ступени усилия, по одной попытке | Показывает механизм, не счёт |
| `chat_result.json` | Три вопроса × три ступени, беседа | То же для разговора |
| `after_result.json` | Полный цикл сразу после первой правки, n=1 | Первый сигнал, что витрина поставлена не туда |
| `recent-commits.txt` | Последние коммиты | Контекст |

## Главное различие, из-за которого была ошибка

**Одна попытка ≠ полный цикл.** Замер по одной попытке показывает, сколько
стоит генерация, если она удалась с первого раза. Продукт живёт полным циклом:
до трёх попыток, каждая оплачена, и повторы бывают чаще, чем кажется — среднее
1,4–2,6 попытки в зависимости от того, что пишется.

Выводы, сделанные по одиночным попыткам, оказались завышены: заявленные
«минус 43 % цены и минус 39 % времени» на полном цикле стали «минус 36 % цены,
времени столько же».

Опираться стоит на `big_result.json`. Остальные три файла — для понимания
устройства, а не для решений.

## Поля

```
cell       что писалось и на каком языке
effort     ступень обдумывания
n          сколько прогонов в клетке
attempts   среднее число попыток на одну выданную вещь
secs       среднее время полного цикла
secs_max   худшее время в клетке
cents      средняя цена всего цикла, в центах США
words      среднее число слов в выданном тексте
```

## Как перемерить

Скрипты замера остались в рабочем каталоге сессии и не переносились сюда:
они требуют ключ Anthropic из `backend/.env`, а его нельзя класть в архив.
Устройство простое — звать `writer.write` с разным `effort` и записывать
`w.attempts`, `w.spend.cents` и время.
